# [초안] 미끼를 깔고, 잡고, 따라가기 — 진행 2 (11/22~11/26)

> 한 줄: 미끼는 혼자 진짜일 수 없고, 탐지는 "어디서 보느냐", 대응은 "언제 도착하느냐"의 문제였다.

## 1. 미끼 배포 — Illusive 맥락 기반 배포
- 벤더: 단말마다 실제 사용 흔적을 보고 그에 맞는 가짜 자격증명을 심는다(특허 US10382483)
- 내 구현: 서버 맥락 수집(값은 안 읽음) → 규칙이 미끼 유형·위치 결정 → 배포·드리프트 감시·교체·회수. 미끼 정의는 코드, 배치는 레지스트리
- 미끼 종류(값은 안 씀): 웹 서버 `.env`의 꺼진 기능 DB 주소, ssh 설정 + 키, 셸 히스토리, 잊힌 ssh-agent, 백그라운드 동기화 프로세스, 옛 AWS 키
- 막힌 점: **맥락 자체를 만들어야 했다** — 고객 단말은 진짜로 쓰이지만 랩 서버는 아니라서, 미끼보다 정상 서버의 사용 흔적이 먼저
- 막힌 점: 미끼는 **내용보다 시각과 순서**에서 들킨다 — 같은 초에 만들어진 파일들, 히스토리 사이에 끼어든 줄, 배포 때 바뀐 디렉터리 시각
- 깨달음: 미끼는 주변 흔적(known_hosts·세션 경계·파일 시각)과 맞물려야 한다. 공격자는 미끼를 "따라가 보는" 순간 그 맞물림을 시험한다

## 2. 트랩·연결 테이블 — 공격자가 믿는 것을 이용
- Illusive 트랩 서버: 운영 서버의 안 쓰는 포트(웹 8080, DB 서버 6379) → 팜의 진짜 서비스로 중계
  - 막힌 점: 주소를 바꿔 중계했더니 Redis `CLIENT LIST`가 중계 주소를 말해 버림 → **서비스는 자기·상대 주소를 고자질한다** → 주소 변환 없는 경로로
- Attivo 연결 테이블 미끼: 공격자는 `ss -tan`을 믿는다 → 디코이로 가는 연결 하나를 걸어 두되 **아무 말도 안 함**
  - 깨달음: "접속 자체가 경보" 원칙이 미끼 스스로 디코이에 닿아야 할 때 무너짐 → 벤더는 경보 조건을 **연결 → 페이로드**로 옮겼다. 스캐너·헬스체크는 조용하고 실제로 뭔가 해야 울림(오탐에도 좋음)

## 3. 탐지 — 어디서 보느냐
- 디코이 밖(팜)에서 탐지: 공격자가 디코이를 장악해도 못 끄고, 디코이가 바깥으로 말할 필요가 없다(바깥 길 = 공격자의 길) — Acalvio가 팜에 탐지를 두는 이유
- 호스트 쪽 미끼 열람 감시: 미끼 파일마다 규칙을 걸면 `auditctl -l`이 **미끼 지도**가 됨 → 미끼를 지목하지 않는 넓은 규칙으로. 대가 = 정상 작업 소음(오탐 글에서)
- 결과: 탐지 경로 8~10개 모두 0.6~2.5초(기준 60초)
- [채울 것] 경보 스크린숏(값 가리기)

## 4. 대응 — 언제 도착하느냐(출발지 포렌식, Illusive)
- 경보가 오면 출발 서버에서 "그 연결을 잡고 있는 프로세스"를 찾아 활동을 기록
- 막힌 점: 원격 수집은 1초도 안 걸리는데 **실패한 로그인 한 번이 그보다 빨리 끝난다** → 프로세스가 이미 없음
- 그래서 tar-pit: 연결을 일부러 늦춰 수집기가 도착할 시간을 범 → Illusive가 tar-pit을 포렌식과 **한 쌍**으로 설계한 이유
- 대가(실측): 투영 디코이 첫 접속 **2.22초** vs 진짜 서버 0.03초 — 접속 시간을 비교하면 드러나는 단서, 한계로 기록
- 포렌식 도구도 공격자 시점에서 검사: 처음엔 공격자의 `ps`에 수집 인자(공격자 pid)가 보였다

## 5. 행동 기록 — 디코이 밖에서 디스크 읽기(Attivo)
- 디코이 안에 아무것도 안 두고 팜이 디코이 VM 디스크를 읽어 세션 명령·만든 파일 회수
- 막힌 점: 실행 중 디스크는 저널을 재생해야 최신이 보이고, 원본을 안 바꾸려면 임시 층이 필요. 파일 내용은 메타데이터보다 늦게 디스크에 닿음
- 깨달음: 하이퍼바이저를 쥐면 디코이 밖에서 다 본다(Attivo가 디코이를 자기 장비 안 VM으로 두는 이유). 대신 수 초 늦고, 메모리에만 있는 건 못 본다

## 6. 체인 — 무엇이 "공격자 한 명"인가
- 흩어진 경보(미끼 열람·디코이 접속·디코이 세션·포렌식)를 **출발 서버 + 로그인 세션**으로 묶음
- IP만으로는 같은 서버의 정상 사용자와 공격자를 못 가름 → 포렌식이 알려 준 프로세스의 세션으로 확정
- 리허설 결과: 시나리오 1의 경보 8종이 **한 체인**으로 — 털린 미끼 → 털린 서버(web-01) → 트랩 → 디코이 → 디코이 안 명령
- 막힌 점: 대응 도구(포렌식 수집기) 자신이 미끼 파일을 읽어 가짜 고리를 만듦
- [채울 것] 체인 출력 스크린숏

## 7. 리허설에 진짜 무기는 필요 없었다
- 탐지는 "어떻게 들어왔나"가 아니라 "미끼를 건드렸나"에 걸린다 → 익스플로잇 없이 **관측치만 재현**해서 검증
- 그래서 안전하게 검증할 수 있지만, 동시에 한계: **미끼를 안 건드리고 지나가는 공격자는 안 걸린다**
- 덤: 규칙은 있는데 그 규칙을 건드리는 검사가 없던 곳(ld.so.preload·cron.d)을 리허설이 찾아냄
